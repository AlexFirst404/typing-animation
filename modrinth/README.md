# Публикация на Modrinth

В этой папке лежит всё, что нужно для страницы мода на Modrinth. Публикует скрипт `scripts/modrinth-publish.mjs`.
Скрипт ничего не отправляет, пока вы явно не попросите: по умолчанию он только всё проверяет.

| Файл | Что это |
|---|---|
| `project.json` | Данные проекта: slug, название, краткое описание (summary), категории, лицензия, ссылки, стороны (клиент/сервер), зависимости, дополнительные загрузчики. |
| `description.md` | Текст страницы проекта (сначала английский, потом русский). |
| `changelog.md` | Список изменений. Прикладывается к каждой версии. |
| `icon.png` | Иконка проекта 512×512 (тот же рисунок, что и `icon.png` внутри мода). |
| `gallery/` | Картинки для вкладки Gallery: 3 GIF и 4 скриншота, а также `gallery.json` со списком, названиями и описаниями. Картинки создаёт `scripts/make-gallery.sh`, `gallery.json` правится вручную. |

## Что понадобится

- Аккаунт на [modrinth.com](https://modrinth.com).
- Node.js 18 или новее (`node --version`). Больше ничего ставить не нужно.
- Собранные jar-файлы в `dist/` (шаг 1).

Все команды ниже запускаются из корня репозитория (`D:\TypingAnimation`). Их можно выполнять и в Git Bash, и в PowerShell. Где синтаксис отличается, приведены оба варианта.

## 1. Собрать jar-файлы

```bash
bash scripts/build-all.sh
```

- В `dist/` должно появиться 29 файлов вида `typinganimation-1.0.0+<версии>-<загрузчик>.jar`.
- Если хотите перед публикацией прогнать ещё и автотест в игре, запустите `SELFTEST=1 bash scripts/build-all.sh`. Он будет открывать окна игры.
- Без bash: `powershell -ExecutionPolicy Bypass -File scripts\build-all.ps1`.

Скрипт публикации берёт jar только из `dist/`. Он проверяет, что файл есть для каждой цели из `targets/`, что внутри правильные метаданные загрузчика и версия мода, и что заявленный в jar диапазон Minecraft совпадает со списком версий для Modrinth.

Публикуйте jar, собранные из того же состояния репозитория, что и коммит релиза. Если исходники цели (`core/`, `mc/<группа>/`, `common-resources/`, `targets/<цель>/`, `scripts/target-common.gradle`) менялись после сборки jar, проверка предупредит об этом: пересоберите такие цели.

## 2. Заполнить `project.json`

Всё, кроме ссылок, уже заполнено. Что можно поправить:

- **Ссылки** `source_url` (исходный код), `issues_url` (баг-трекер), `wiki_url`, `discord_url`, `license_url`.
  - Сейчас они `null`, то есть не заданы.
  - Чтобы задать ссылку, впишите полный адрес с `https://`, например `"source_url": "https://github.com/<вы>/TypingAnimation"`. Адреса с `http://` Modrinth не примет.
  - Модераторы Modrinth хорошо относятся к ссылке на исходники и баг-трекер, но это не обязательно.
- **`summary`**: краткое описание под названием проекта, не длиннее 255 символов.
- **`categories`**: сейчас `utility` и `social` (мод про ввод текста и чат). Можно указать до 3 основных категорий, остальные идут в `additional_categories`. Допустимые значения скрипт выводит при ошибке.
- **`client_side`: `required`, `server_side`: `unsupported`, `environment`: `client_only`**: мод только клиентский.
  - `environment` — новое поле Modrinth, оно ставится у каждой версии.
  - Без него Modrinth записал бы у версий «unknown».
- **`dependencies_by_loader`**: зависимости для каждого загрузчика. Сейчас у Fabric-версий указан Mod Menu как необязательная зависимость (`optional`).
- **`extra_loaders`**: дополнительные теги загрузчиков для отдельных сборок. Ключ — имя папки в `targets/`. Добавляйте загрузчик, только если сборка на нём действительно проверена и загружается на его текущей стабильной версии: лаунчеры предлагают файл всем сборкам с этим загрузчиком, а страницу мода при этом никто не видит. Сейчас там:
  - `1.20.1-forge` → `neoforge`: Forge-сборка проверена на NeoForge 1.20.1 (47.1.106), автотест прошёл полностью.
  - `1.20.1-fabric`, `1.21.1-fabric`, `1.21.11-fabric`, `26.2-fabric` → `quilt`: проверены на Quilt Loader 0.30.1 (текущая стабильная версия).
  - `26.3-fabric` без `quilt`: работает на Quilt Loader 0.31.0-beta.4, но стабильный 0.30.1 отказывается её загружать (он предоставляет fabricloader версии 0.19.3, а сборке нужен 0.19.5 или новее). Когда выйдет стабильный Quilt Loader, который её загружает, проверьте и добавьте `quilt`.
  - Остальные Fabric-сборки на Quilt не проверялись.
  - Те же сведения есть в `description.md` (раздел Quilt). Меняете одно — поправьте и другое.

Тексты страницы и изменений правятся в `description.md` и `changelog.md` (Markdown в формате Modrinth). В `description.md` нельзя ссылаться на картинки из этой папки: у них нет адреса в интернете. Сначала загрузите их в галерею (шаг 7), потом при желании вставьте в текст их адрес `https://cdn.modrinth.com/...`.

## 3. Проверка (dry run)

```bash
node scripts/modrinth-publish.mjs
```

Токен для проверки не нужен, на Modrinth ничего не отправляется. Скрипт:

- читает `targets/*/target.properties`, `dist/*.jar` и эту папку;
- разворачивает диапазоны версий Minecraft по манифесту Mojang (только релизы): например, `1.21.6-1.21.8` превращается в 1.21.6, 1.21.7 и 1.21.8;
- сверяет версии игры, загрузчики, категории, лицензию и зависимости с публичным API Modrinth;
- проверяет ограничения Modrinth на длину полей, `version_number` (до 32 символов), размер иконки и картинок;
- проверяет байткод Fabric-сборок: `@Redirect` с `at` в виде массива (так пишет javac, если собрать против Mixin из Fabric Loader 0.19.5) роняет игру на Fabric Loader 0.15.0–0.19.4 и Quilt Loader 0.30.1, поэтому такая сборка с минимальным fabricloader ниже 0.19.5 считается ошибкой (подробнее в `scripts/target-common.gradle` и `docs/SPEC.md`, раздел 1);
- предупреждает о jar, собранных раньше последнего изменения исходников своей цели;
- печатает таблицу всех 29 версий и в конце пишет `DRY RUN OK` или список ошибок.

Полезные варианты:

- `node scripts/modrinth-publish.mjs --json` — показать, что именно уйдёт на Modrinth для каждой версии.
- `node scripts/modrinth-publish.mjs --only 26.3-neoforge,26.3-fabric` — проверить только часть сборок.

Как устроены версии:

- **Номер версии:** `1.0.0+<диапазон>-<загрузчик>`, например `1.0.0+1.21.6-1.21.8-fabric`.
- **Название:** например `1.0.0 Fabric 1.21.6-1.21.8`.
- **Отмечены как Featured:** самые новые версии каждого загрузчика (сейчас это 26.3).
- **Порядок загрузки:** от старых версий Minecraft к новым, поэтому на Modrinth новые окажутся сверху.

## 4. Создать токен (Personal Access Token)

1. Войдите на modrinth.com и откройте **Settings → Personal access tokens** ([modrinth.com/settings/pats](https://modrinth.com/settings/pats)).
2. Нажмите **Create a PAT**, дайте токену имя (например, `typing-animation-release`) и срок действия (хватит нескольких дней).
3. Отметьте только эти права (scopes):

   | В интерфейсе | Внутреннее имя | Зачем |
   |---|---|---|
   | Create projects | `PROJECT_CREATE` | `--create-project` |
   | Read projects | `PROJECT_READ` | читать черновик проекта |
   | Write projects | `PROJECT_WRITE` | `--sync-project`: текст, иконка, галерея |
   | Read versions | `VERSION_READ` | узнать, какие версии уже загружены |
   | Create versions | `VERSION_CREATE` | `--publish` |

4. Скопируйте токен: он начинается с `mrp_` и показывается один раз.

Токен — это пароль к вашему аккаунту:

- Не сохраняйте его в файлы репозитория и не передавайте аргументом командной строки.
- Скрипт читает его только из переменной окружения `MODRINTH_TOKEN` и никогда не выводит на экран.
- После публикации токен можно удалить на той же странице.

## 5. Задать переменные окружения

Токен лучше вводить так, чтобы он не попал в историю команд.

**Git Bash:**

```bash
read -rsp "Modrinth token: " MODRINTH_TOKEN; echo; export MODRINTH_TOKEN
```

**PowerShell:**

```powershell
$env:MODRINTH_TOKEN = [Net.NetworkCredential]::new('', (Read-Host 'Modrinth token' -AsSecureString)).Password
```

Переменные действуют, пока открыто это окно терминала.

## 6. Создать проект (черновик)

```bash
node scripts/modrinth-publish.mjs --create-project
```

Скрипт создаёт черновик (draft), то есть проект пока виден только вам.

- В черновик сразу попадают название, slug `typing-animation`, краткое описание, текст страницы, категории, лицензия MIT, ссылки (если заданы) и иконка.
- Если slug уже занят, скрипт остановится и ничего не создаст.
- В конце скрипт печатает **id проекта**. Сохраните его в переменную:

```bash
export MODRINTH_PROJECT=<id>          # Git Bash
```

```powershell
$env:MODRINTH_PROJECT = '<id>'        # PowerShell
```

Вместо id можно указать slug: `typing-animation`.

## 7. Галерея и обновление страницы (`--sync-project`)

Галерея уже готова: 7 файлов в `modrinth/gallery/` перечислены в `gallery/gallery.json`.

| Файл | Что показывает |
|---|---|
| `chat-typing.gif` | набор в чате: вставка в середину строки, удаление, вставка из буфера, отправка |
| `command-highlighting.gif` | команда с подсветкой и автодополнением по Tab |
| `styles.gif` | стили Pop, Scramble, Wave и Drop крупным планом |
| `chat-in-world.png` | чат в мире, **главная картинка** (`featured`) — её Modrinth показывает в поиске |
| `config-screen-en.png`, `config-screen-ru.png` | экран настроек на английском и русском |
| `options-button.png` | кнопка в «Настройках» |

1. **Пересоздать медиа** (например, после изменений в моде): `bash scripts/make-gallery.sh`.
   - Откроется окно Minecraft 26.3 примерно на 2 минуты. Скрипт сам печатает в чат настоящего мира и записывает кадры во временную папку (не в репозиторий).
   - `bash scripts/make-gallery.sh --reuse` только пересобирает файлы из последней записи.
   - `gallery.json` скрипт не трогает: названия и описания правятся вручную.
2. **Добавить свою картинку:** положите файл в `modrinth/gallery/` и допишите запись в `gallery.json`:

```json
{ "file": "my-screenshot.png", "title": "Unique title", "description": "What it shows.", "featured": false, "ordering": 7 }
```

   - Форматы: png, jpg, webp, gif. Размер каждого файла — до 5 МиБ.
   - `title` обязателен и должен быть уникальным: по нему скрипт узнаёт уже загруженные картинки.
   - `featured: true` можно поставить только у одной картинки.
   - Проверка (`node scripts/modrinth-publish.mjs`) печатает список галереи, ругается на отсутствующие файлы и предупреждает о картинках в папке, которых нет в `gallery.json`.
3. Запустите:

```bash
node scripts/modrinth-publish.mjs --sync-project
```

Что делает эта команда:

- Обновляет название, краткое описание, текст страницы, категории, лицензию и заданные ссылки.
- Заново загружает иконку.
- Загружает картинки галереи, которых на Modrinth ещё нет. Картинка с таким же `title` пропускается.

Команду можно запускать сколько угодно раз, например после каждой правки `description.md`. Ссылки со значением `null` скрипт не трогает: если вы задали ссылку на сайте Modrinth, она сохранится. Удалять и менять уже загруженные картинки нужно на сайте, во вкладке Gallery.

## 8. Загрузить версии (`--publish`)

Сначала можно попробовать одну версию:

```bash
node scripts/modrinth-publish.mjs --publish --only 26.3-neoforge
```

Потом все остальные:

```bash
node scripts/modrinth-publish.mjs --publish
```

- Перед загрузкой скрипт проходит все проверки из шага 3. Если есть хоть одна ошибка, он ничего не отправляет.
- Предупреждения загрузку не останавливают, поэтому прочитайте их. Предупреждение о jar, который старше исходников, значит, что файл не соответствует коммиту: пересоберите его и запустите команду снова.
- Версии с уже существующим на проекте `version_number` пропускаются, поэтому команду можно безопасно повторять.
- Если Modrinth вернёт ошибку, скрипт покажет её текст (JSON от Modrinth) и остановится. Исправьте причину и запустите команду снова: уже загруженные версии будут пропущены.
- Если Modrinth ограничит частоту запросов (HTTP 429), скрипт сам подождёт и повторит запрос.
- Если jar на Modrinth отличается от файла в `dist/`, скрипт предупредит, но заменять ничего не будет. Заменить файл можно на сайте, или удалите версию там и запустите `--publish` снова.

## 9. Проверить страницу и отправить на модерацию

1. Откройте `https://modrinth.com/mod/typing-animation` (черновик виден только вам) и проверьте:
   - текст на странице;
   - вкладку Versions: 29 версий, у каждой правильные версии игры и загрузчики, у Fabric-версий есть Mod Menu в зависимостях;
   - дополнительные загрузчики: у Forge-версии 1.20–1.20.1 ещё NeoForge, у Fabric-версий 1.20–1.20.1, 1.21–1.21.1, 1.21.11 и 26.2 ещё Quilt (у 26.3 — нет);
   - вкладку Gallery: 7 картинок, GIF анимируются, главная — «In the world»;
   - что проект отмечен как клиентский;
   - лицензию и ссылки.
2. Проверьте в настройках проекта раздел про раскрытие информации (Disclosures), если он там есть.
   - Modrinth просит отметить, например, телеметрию, рекламу или использование ИИ.
   - Телеметрии и рекламы в моде нет.
   - Код мода написан с помощью ИИ-агентов. Если Modrinth просит раскрывать такое, отметьте это честно.
3. Нажмите **Submit for review** на странице проекта.
   - Модераторы проверят проект, обычно это занимает от нескольких часов до нескольких дней.
   - После одобрения проект станет публичным.
   - Если модераторы что-то попросят исправить, их сообщение придёт в уведомления и в ветку модерации проекта.

## Пробный запуск на staging (необязательно)

У Modrinth есть тестовый сервер: [staging.modrinth.com](https://staging.modrinth.com).

- Аккаунт и токен для него создаются отдельно, прямо на staging.
- Добавьте ко всем командам флаг `--staging`, например `node scripts/modrinth-publish.mjs --create-project --staging`.
- Можно и задать адрес API вручную: `MODRINTH_API_URL=https://staging-api.modrinth.com/v2`.

## Следующие версии мода

1. Поднимите версию в `scripts/target-common.gradle` (`def MOD_VERSION = '...'`).
2. Допишите новый раздел в начало `changelog.md` (весь файл прикладывается к каждой новой версии, так что старые разделы можно удалить).
3. Пересоберите jar (`bash scripts/build-all.sh`) и запустите проверку. Старые jar в `dist/` скрипт не загружает, только предупреждает о них, так что их можно удалить.
4. Задайте `MODRINTH_TOKEN` и `MODRINTH_PROJECT` и запустите `node scripts/modrinth-publish.mjs --publish`.
5. Новые версии получат отметку Featured. У старых эту отметку можно снять на сайте.
6. Если появилась новая цель в `targets/`, скрипт подхватит её сам. Строку в таблице версий в `description.md` добавьте вручную, потом выполните `--sync-project`.
